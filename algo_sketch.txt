Just describing two pieces here and not the details.

IFAProcessor: an object similar to PFAEngine:
	- takes in:
	- a path to a cphd (not the CPHDReader and SICDWriter)
		- in fact, since we got rid of sarpy, the abstraction we build may no longer be needed
		- exposing the cphdreader and sicdwriter to the user was not the intent
		- we can work with sarkit directly as long as the algo logic isn't exposed to it
			- the algos should work variables and whatever abstraction IFAProcessor creates
			- it's fine for IFAProcessor to contain the particulars of sarkit
				- as long as they don't leak to the algos outside of IFAProcessor
		-  a path the the sicd
			- same comments as above
		-  an Area
			- options are ImageArea, ExtendedArea, Custom
			- option for custom area
		- in a SampleSpacing
			- options are Default, Custom
	- on init
		- grabs needed metadata
	- on run
		- parallel load of channels into ram
			- in the future we may need to delay this to the IFP_PerPol to save ram
				- don't take action on this note (it is for the human)
		- sorts channels into lists for calling IFP_PerPolar for each polarization to be saved
		- calls IFP_PerPolar with all cpu args
			- receives back cpu image
		- saves sicd
		

In another file:

IFP_PerPolar: a function that works per polarization
	- takes in 
		- every channel of a polarization group in a list of numpy arry
		- appriopriate pvp data in a list of array for each channel
		- appropriate metadata
		- these are on cpu, no gpu yet, we are tyring to delay copies to gpu until needed
	- calculates current kspace coordicates for current polar formated data
		- perhaps this is a list of kspaces (one for each channel)
	- caluclates shared kspace coordinate for the final kspace frequency data
		- should use the inscribed limits of all the channels' current kspace
	- allocates memory on the GPU for the kspace frequency data
	- for each channel:
		- copies channel and other needed data to gpu
		- performs the per channel pfa implementation
			- which points the the shared kspace
			- so the per channel implementation takes incoming data and reference to the share kspace
		- frees gpu resources
	- performs final 2d ifft for image formation
	- copies data back to cpu
	- frees gpu resources, including the large shared kspace
	- return cpu image to the IFAProcesor
